# 部署交付清单

[English](release-checklist.en.md)

部署须同时符合 [版本与模式合同](../README.md#支持的后端与版本)、[控制能力约束](certification.md) 和 [配置参考](configuration.md)。

## 构建与运行材料

- 使用完整源码和 crates.io 锁定依赖，保留 Apache-2.0 及适用的第三方许可证。
- 源码分发保留 `Cargo.toml`、`Cargo.lock`、构建脚本、协议文件、源码、引导配置与文档；本项目保持 `publish = false`，不向 crates.io 上传 NARIX。
- 外部配置、节点本地路径和权限有效；文件选择优先级为 `--config` → `APP_CONFIG_FILE` → `NARIX_CONFIG`，明确指定的错误路径不能静默回退。
- 日志目录可写，容量、保留策略和关闭预算符合部署资源。空路径或 null 只输出控制台。
- 至少配置一个业务代理；空 `proxies` 仅用于同时开启管理端和 reload 的待配置状态。

## 接入与访问控制

- 管理端设置强 token 并限制网络入口；业务前端认证与后端最小权限分别配置。
- 跨不可信网络的业务入口由受信设施终止 TLS；后端、Sentinel 和协调 gRPC 的证书分别配置。
- readonly 设置 `read_only: true`；`observer` 仅约束控制写，不能代替业务只读策略。
- 连接、pipeline、专用连接池、排队、帧大小和超时符合文件描述符、后端 maxclients 与内存预算。
- 节点代理地址映射覆盖拓扑公布和重定向地址；Pika/Codis 槽接口不配置为标准 Cluster。

## HA 与持久化

- Dragonfly 使用 `backend_profile: dragonfly` 与 `mode: replication-ha`；多机控制面优先部署至少三个协调成员，数据节点按一主、无快照热备与快照副本规划。
- 同组后端仅有一个有效写控制面，多实例使用匹配的协调方式；跨主机开启 mTLS 并绑定成员证书指纹。
- 静态成员表固定，2/2 或多数派不足时保持保护，不能临时删除缺席成员。
- 隔离脚本保证真实 fencing 并拒绝过期动作；`manual` 不提供物理隔离保证。
- 负载均衡按 `/ready` 摘挂，监控角色、复制、保护原因、租约和动作状态；TCP 握手不能替代业务就绪。
- 先启用并验证新 owner，再停用旧 owner，提交后发布；缺席、写入失败或 checkpoint 无法确认时按 `fail_closed` 保持保护。
- Kvrocks 保留各节点 RocksDB/WAL 并关闭 NARIX 持久化编排。其他产品的目录、备份、恢复与磁盘容量符合原生要求。
- 已报告的额外 master 未隔离或降级前，不通过重启或配置替换清空风险证据；缺席不是已隔离的证明。

## 配置变更与停止

- reload 只经配置事务发布，同代日志、凭据、路由和监听器准备完整后才激活，失败不开放混合配置。
- 协调成员对齐 application 元数据及托管配置，节点本地日志、证书、地址和目录分别保留；混合可执行版本不自动保证管理动作和超时语义相同。
- 已提交配置的本地激活失败时保持保护并恢复已提交状态，不自行回退共识事实。
- 停止先撤销业务准入，再停止控制任务、排空连接，最后关闭日志；非零退出或关闭超时不能视为正常排空。
- 自动拉起区分配置、启动及运行失败；维护时保留角色、协调状态和持久化事实，支持安全恢复。
